## 2. Cosmetics (10k+), avatars, banners, badges, frames, icons
**Wants:** a 12,000+ design universe, endless new items, real rendered art (not one template), AAA avatar quality (3D), no "Numbered x of y", unlimited prestige copies, no vault retirement, long cooldowns, honest pricing with a "How is this priced?" explainer.
**Exists:** `src/cosmetic-universe.js`: deterministic, unbounded catalog, UNIVERSE_SIZE 12,000 browsable designs, names are a bijection of the index (no serials; edition numeral only when a 1,200-combo name space is exhausted), 3 themes (culture, gaming, money), types banner/frame/title/badge/color/effect (+avatar parts); index%3==2 are earn-only (achievements/quests/season), others sold. Shop engine `src/shop.js` + `shop-gen.js`: deterministic simulation from EPOCH_DAY 2026-10-01 (daily 6 items incl. a Vault slot, weekly 4 epic/legendary, season shop 6, 10 recurring yearly events, earned items). Rarities common/rare/epic/legendary. **Cooldowns now 60/120/180/270 days** (COOL; legacy 10/14/21/28 + caps only for days before the cutover 2026-10-18 — docs/ECONOMY.md still describes the legacy numbers: stale); scarcity clamp MIN_ACTIVE_FOR_SCARCITY=500. Prestige: 12 hand-authored originals ($1,000–$5,000) shown as preview-only (`PRESTIGE_SALES_ENABLED` unset); supply cap removed (unlimited, one per player per SYSTEMS-PLAN) — **docs/ONE-OF-ONE-PRESTIGE-COLLECTIBLES.md is the OLD one-of-one spec and conflicts; Reese's current rule is unlimited copies, no 'Numbered/1 of 1' wording — update that doc.** Pricing modal exists (economy.js, hub-store.js). Avatars: editor with ~70 parts, server-rendered SVG + 3D preview (avatar-3d.js) that still says "compatibility preview · rigged wardrobe asset pending". Cosmetic CSS served via `/cosmetics.css`, per-player `/cosmetics-mine.css` (cap 400).
**Remains:** (a) item art quality: replace the single SVG template with per-type renderers (lit metal, gems, foil, scenes) — audit tier 2 today; (b) avatar 3D: real rigged wardrobe (glTF from CC0 sources or original), remove the pending banner, mobile perf budget; (c) prestige: bespoke geometry, included variations, compatibility manifest, then enable sales only after payment/refund review; (d) counts: report unique meshes vs variants honestly (docs/AVATAR-CATALOG-SHARED-GAMES-AAA-AUDIT.md rule: never advertise an item count without a generated report); (e) update stale docs; (f) icons: achievements use icon-font names → real icon set (src/icons / public/js/icons.js).
**Acceptance:** 12,000 unique-named items browsable with no duplicate names; each type has a distinct render at 1x/2x on 390px; shop rotation test (`tools/e2e-economy.js`, e2e-timers) green; no "Numbered"/"x of y" strings (`grep -ri "of 1\b\|numbered" public src`); cooldown values 60/120/180/270 asserted in a test; avatar editor loads in <3 s on mid phone and ≤ budget memory; price modal one line + collapsed explainer at 320px.

## 9. Scale: 10k+ concurrent
**Wants:** the hub must survive 10k+ concurrent users (stated goal; current host is the free Deplexo plan).
**Exists / measured (local, Dockerfile flags):** after fixes ~340 req/s, 200 concurrent 0 errors, p95 0.5–0.9 s; ~1% errors at 300; capacity ≈150–200 concurrent on the free host; a clean 20k-user run to 500–1000 concurrent was NOT achieved. Fixes: scrypt, statement cache, board memo, cssKey memo.
**Plan:** Phase 0 (free tier): immutable cached versioned assets (done for hub assets; add `?v=` to /games-lib), edge caching of read APIs (leaderboards, games, shop) with short TTL+ETag, polling ≥15–30 s with jitter, no websockets. Phase 1: paid host ≥2 vCPU/2 GB, remove `--no-opt`, keep SQLite+WAL (tens of writes/s are fine). Phase 2 (≥2–3k concurrent): Postgres (managed), Redis for rate limits/sessions/leaderboards (sorted sets), N stateless app nodes behind a load balancer, CDN in front of all static + game assets, background job worker for results/backups, object storage for media. Realtime: only if duels ship (V1.1 casual duels spec) — use queue + polling first; SSE/websockets via a separate gateway. Rate limits per IP/user via shared store, trusted proxy hops configured. DB migration: write a SQLite→Postgres migration script and dual-run tests; keep `better-sqlite3` for dev. Targets: 10k concurrent browsing sessions at ≥2k req/s peak on the API tier with p95 <500 ms, error <0.5%, CDN hit ratio >90% for static, DB CPU <60%; load-test with k6/autocannon on a staging copy, never on the free host.
**Acceptance:** staged load tests (1k→5k→10k virtual users) pass the targets on the new stack; failover test; cost estimate approved by Reese (UNKNOWN budget).

## 11. Full QA checklist & definition of done
Run at 390px, 320px, desktop; signed-out and signed-in; EN + one RTL language; software-GL box plus real iPhone + Android.
- **Shell/pages:** Home, Games (cards/filters/search), each game page (launch, guest mode toast, sign-in-to-save, pause/resume, game-over, restart), Leaderboards (all/weekly/monthly/friends/per game), Giveaways (list, detail, join, rules, eligibility messages, official event code entry), Tournaments, Season, Quests, Achievements, Community/profile/follow/invite, Shop (rotation, countdowns, price modal, buy with Credits, cash checkout), Store (packs/pass/prestige preview), Avatar editor, Settings (privacy, export, delete), Notifications, Sponsor/Book a giveaway, Brand pages + Featured Brands, About, Terms, Privacy, Rules, sign-up (21+), sign-in/out, password change, reset, offline, 404/500, share links `/s/<id>` + OG images, SW update after deploy, sitemap/robots.
- **Every game:** 1.4 gate. **Every admin page:** 25 pages load, no console errors, actions work, role limits enforced.
- **Systems:** payments (Stripe sandbox purchase/refund), backups, rate limits, cache-busting after deploy, memory (mem-check <100 MB), load (supported concurrency).
- **Definition of done:** all suites green; 0 console errors; every game ≥7/10 and honestly classified; legal review recorded; Stripe live verified by Reese; docs updated (this spec, GAMES-LIB.md, RELEASE-REPORT.md); main in sync via PR; live smoke GETs pass.
