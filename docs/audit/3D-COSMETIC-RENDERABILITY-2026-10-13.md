# Cosmetic 3D renderability checkpoint — 2026-10-13
The owner's Android screenshots show an unacceptable procedural blob avatar and generically illustrated shop cards. The live implementation's rotating v7 generator currently creates **CSS/SVG profile assets** (banner/frame/color/title/badge/effect). These remain legitimate 2D profile cosmetics, but they are **not** thousands of real 3D hair, clothing, shoes, props or emotes. Treat actual wearable GLBs as a separate asset pipeline with exact mesh/material/animation/provenance, entitlement and device performance signoff; no auto-approved listings.

`tools/audit-3d-cosmetics.js` is a **read-only audit** run against a stub database. It counts actual avatar part rows, checks shipped rig sources and incompatible starter rendering, and writes `docs/audit/wardrobe-renderability.json`. The generated sample is a profile cosmetic, not a 3D asset. The source fact `supportsRiggedAvatar()` requiring `outfit:'adventurer'` while starter `outfit:'base'` remains a blocker. Don't fix it by dressing every new user as Adventurer. Retain all saved entitlements and free-face decisions.

All 3D wardrobe SKUs require an explicit compatible glTF / GLB mesh, skeleton and socket mapping, PBR source texture set, preview screenshot, supported mobile LOD and licensing evidence before monetization. A blue recolored primitive or icon does not meet acceptance. Quaternius Universal Base Characters (6 bodies, 20 hair) and Modular Outfits (12 themed, 62 parts) are prospective CC0 **sources**, not yet transferred and approved. Source research and asset sourcing are separate from deployed build or public launch.

This audit branch is isolated: no changes to production checkout, avatar ownership, ratings, real user data or game scores. See issue #18.
