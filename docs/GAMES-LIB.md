## How it fits together
- Files: `public/games-lib/<slug>/` (index.html, game.js, CREDITS.md, thumb.jpg, LICENSE for vendored code). Shared engine code: `kit.js` (canvas, input, touch stick/buttons, particles, WebAudio SFX, title/game-over), `adapter.js` (Hub run session), `runner3d.js`, `td.js`, `arena.js` (shared mechanics engines).
- Registry: `src/games-lib.js` (metadata card: category, tier, competition type, scoring, event length, giveaway_eligible, anti-cheat level L2, rate ceiling, source + licence). Served at `GET /api/games-lib`; library page `/games-lib/index.html`.
- Scoring: `adapter.js` calls `POST /api/run/start` (signed single-use token + seed) when a run begins, logs scoring events in the L3 event format of `src/ac-levels.js` plus input telemetry, and submits `POST /api/score` at game over. Server checks (L2): token signature/owner/TTL/single use, server-measured time vs the per-game rate ceiling (flag above perSec*t+grace, hard reject above 2x), telemetry, submit bursts.
- Shared-file hooks (all marked `[games-lib hook]`): `src/config.js` (GAME_MAP/gameInfo/giveawayEligible include library games; LIB_GAMES export), `src/server.js` (mount GET /api/games-lib), `src/results.js` (giveaway cap SQL includes library games), `public/js/app.js` (link to the library from /games).
- Tests: `BASE=http://localhost:8795 node tools/e2e-games-lib.js [slugs]` (desktop + iPhone 13, random input session, console errors, accepted legit score, rejected forged score, FPS, thumbnail capture).

## Sourcing research (picked vs rejected)
For each reference we searched GitHub (topics html5-game / javascript-game / phaser, awesome-html5-games, awesome-js-games), itch.io (HTML5 + MIT/CC0), js13kGames entries, Libre Arcade, OpenGames, H5 Arcade, OpenGameArt/Kenney (CC0 art), Phaser examples, GDevelop/Construct examples and Godot web exports, plus the 120 pre-verified rows in docs/GAME-CANDIDATES.md. A candidate is only vendored when BOTH its code licence and every bundled asset (sprites, sounds, fonts) are cleanly licensed and it can be stripped of trademarks. Most faithful clones of commercial games ship ripped sprites/sounds from the original (code MIT, assets not), which disqualifies them; in those cases we BUILD an original version.

## Giveaway eligibility, skill tie-breaks and playoffs

**Eligible: 60/60 (100%)** - Reese's rule (Oct 10 2026): 100% of listed games must be giveaway-eligible: an endless mode with an uncapped score, skill-based scoring, anti-cheat L2+. No chance-only games and no external "just for fun" links are listed; `tools/e2e-games-lib.js` fails if any listed game is not eligible or lacks a tie-break.

**Exactly one winner, skill only.** Ranking = best single-run score. Ties are broken ONLY by skill metrics the server derives from the run itself (`src/games-lib-playoff.js`, its own tables `lib_run_metrics`, `lib_playoffs`, `lib_playoff_entries`): M1 = faster server-timed run to the same score (run end minus server-issued start), M2 = a per-game skill count taken from the signed run's event log (or points per scoring action = efficiency). Submission time, first-to-score and attempt counts are never used. A run whose event log does not add up to its score gets null metrics and ranks last among equal scores.

**Sudden-death playoff.** If players are still exactly tied on score, M1 and M2, an admin starts a playoff (`POST /api/admin/games-lib/playoffs` with `game_id` + `user_ids`, or `game_id` + `start`/`end` to pick up the tied group automatically; `window_min` sets the window). Each tied player gets ONE run (`/api/run/start` with `playoff`), all with the same server seed, inside the window. `POST /api/admin/games-lib/playoffs/:id/resolve` ranks the playoff runs by score then M1/M2; no-shows rank last; an exact tie again opens the next round automatically with a new seed. Players see open playoffs via `GET /api/games-lib/playoffs/mine`. The module is separate from the core events code (src/events.js) and joins it only through 5 marked `[games-lib hook]` lines in src/server.js.
